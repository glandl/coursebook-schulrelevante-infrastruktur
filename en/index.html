                    • Documentation techniques

                      This chapter is the continuous script on documentation. It follows the order of the sessions, so each technique builds on the previous one. The session chapters only refer here: this is where how to document is explained, while the sessions say what to document. All submissions go into the portfolio repository (private, pull requests) and are assessed with the assessment rubric. Why document? School IT is rarely run by one person alone, and rarely by the same person for long. Whoever leaves the school, goes on parental leave or falls ill takes their knowledge with them if it has not been written down. Good documentation

                    • Virtualization & Containerization

                      Session: 05.10.2026 · Documentation technique: Markdown, Git and pull request workflow · Homework due: 18.10.2026 Schools run a few servers for many tasks: learning platform, file storage, directory service, print server, administration software. In the past every task got its own computer, today they run on virtual machines or in containers. This saves hardware and electricity, makes backups and updates plannable, and allows changes to be tried out safely. In this session you learn how virtualization and containerization work, when to use which technique, and how to build a Linux VM and a Docker service in a laptop lab. Everything runs on your laptop with free software.
